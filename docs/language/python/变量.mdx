## [变量](https://realpython.com/python-variables/)

### 认识 Python 中的变量

在 Python 中，变量是与计算机内存中存储的具体对象或值相关联的名称。通过将变量与值关联，你可以使用具有描述性的名称来引用该值，并在代码中根据需要多次复用它。

变量的行为就像它们所引用的值一样。要在代码中使用变量，首先需要学习如何创建它们，这在 Python 中非常直观明了。

### 通过赋值创建变量

在 Python 中创建变量的主要方式是使用赋值运算符（assignment operator），其语法如下：

```python
variable_name = value
```

在该语法中，左侧是变量名，接着是赋值运算符（`=`），右侧则是要赋给该变量的值。此处的赋值对象可以是任何 Python 对象，包括[字符串](https://realpython.com/python-strings/)、[数字](https://realpython.com/python-numbers/)、[列表](https://realpython.com/python-list/)、[字典](https://realpython.com/python-dicts/)，甚至是自定义对象。

### Python 中的变量命名

前面的示例使用的是简短的变量名。在实际开发中，变量名应当具有描述性以提高代码的可读性，因此变量名往往较长且包含多个单词。

在以下部分中，你将学习在 Python 中创建有效变量名所要遵循的规则，以及变量命名的最佳实践。

#### 变量命名规则

Python 中的变量名可以是任意长度，可以由大写字母（A-Z）、小写字母（a-z）、数字（0-9）和下划线（`_`）组成。唯一的限制是：**虽然变量名可以包含数字，但变量名的第一个字符不能是数字**。

:::note[提示]

Python 目前具备完整的 [Unicode](https://realpython.com/python-encodings-guide/) 支持，变量名中可以使用许多 Unicode 字符。例如，以下变量名都是有效的：

```python
>>> α = 45
>>> β = 90
>>> δ = 180
>>> π = 3.14
```

这些变量名在常规 Python 代码中可能不常见，但完全合法。在执行科学计算时，如果你希望代码贴合对应学科的符号表示，可以使用它们。

:::


以下都是合法的变量名：

```python
>>> name = "Bob"
>>> year_of_birth = 1970
>>> is_adult = True
```

这些变量符合在 Python 中创建有效变量名的规则，同时也遵循了最佳命名实践。

而下面的变量名不符合规则：

```python
>>> 1099_filed = False
  File "<input>", line 1
    1099_filed = False
    ^
SyntaxError: invalid decimal literal
```

此例中的变量名以数字开头，这在 Python 中是不允许的，因此会引发 [SyntaxError](https://realpython.com/invalid-syntax-python/) 异常。

另外需要特别注意：**变量名大小写敏感**。小写字母和大写字母被视为不同的字符：

```python
>>> age = 1
>>> Age = 2
>>> aGe = 3
>>> AGE = 4
>>> age
1
>>> Age
2
>>> aGe
3
>>> AGE
4
```

在此示例中，Python 将这些名称解释为完全不同且相互独立的变量。因此在 Python 中命名变量时必须考虑大小写。

虽然语法上并不阻止你在同一个程序中创建名为 `age`、`Age` 或 `agE` 的多个变量，但极不推荐这种做法，因为它会让阅读代码的人（甚至是过了一段时间后的你自己）感到困惑。通常情况下，创建变量名时应一律使用小写字母。

下划线字符的作用也十分关键。你可以使用下划线来分隔变量名中的多个单词：

```python
>>> first_name = "John"
>>> pen_color = "red"
>>> next_node = 123
```

在这些变量名中，下划线用作多单词之间的分隔符，通过替代空格来提高代码的可读性。对比一下如果没有下划线的效果：

```python
>>> firstname = "John"
>>> pencolor = "red"
>>> nextnode = 123
```

尽管这些名称在技术上合法，但一眼看上去很难阅读和理解。缺少分隔让快速理解每个变量的含义变得更加困难。使用下划线能显著提高代码的清晰度与可维护性。

#### 变量命名最佳实践

应当始终给变量赋予具有描述性、能清晰解释其用途的名称。有时可以用单个单词来命名变量：

```python
>>> temperature = 25
>>> weight = 54.5
>>> message = "Hello, Pythonista!"
```

变量始终引用具体的对象，因此其名称通常应为**名词**。应当为变量寻找具体的名字以唯一标识所引用的对象。类似 `variable`、`data` 或 `value` 这样的名字过于宽泛，虽然在简短的示例中可用，但在生产代码中缺乏足够的描述性。

通常应避免使用单字母名称：

```python
>>> t = 25  # 不推荐
>>> temperature = 25  # 推荐
```

单字母名称难以辨析，尤其是在与其他类似名称一起出现在复杂表达式中时，会导致代码可读性变差。当然也有例外，例如在处理嵌套列表或矩阵时，可以使用单字母名称表示索引：

```python
>>> matrix = [
...     [9, 3, 8],
...     [4, 5, 2],
...     [6, 4, 3],
... ]
>>> for i in matrix:
...     for j in i:
...         print(j)
...
9
3
8
4
5
2
6
4
3
```

通常使用 `i`、`j`、`k` 表示索引，在合适的上下文中这样使用是完全可接受的；同样，使用 `x`、`y`、`z` 表示坐标点也是常见做法。

不鼓励使用缩写来命名变量，提倡使用完整名称：

```python
>>> doc = "Freud"  # 不推荐
>>> doctor = "Freud"  # 推荐
```

使用完整名称更为清晰易读。不过，在一些已被广泛接受和通用的缩写场景下也是可以的：

```python
>>> cmd = "python -m pip list"
>>> msg = "Hello, Pythonista!"
```

在这些示例中，`cmd` 是 `command` 的公认缩写，`msg` 是 `message` 的公认缩写。Python 中广泛使用的缩写经典例子还有 `cls`，用于在[类方法（class method）](https://realpython.com/ref/glossary/class-method/)中表示当前类对象。

有时需要多个单词才能组成一个具有描述性的变量名。如果多单词之间没有明显界限，阅读起来会非常费力：

```python
>>> numberofgraduates = 200
```

这种变量名难以阅读，必须仔细辨认单词边界才能理解其含义。

多单词变量名最常见的命名风格有以下几种：

- **[蛇形命名法（Snake case）](https://realpython.com/ref/glossary/snake-case/)**：小写单词之间用下划线分隔。例如：`number_of_graduates`。
- **[驼峰命名法（Camel case）](https://realpython.com/ref/glossary/camel-case/)**：第二个及后续单词首字母大写。例如：`numberOfGraduates`。
- **[帕斯卡命名法（Pascal case）](https://realpython.com/ref/computer-science-glossary/pascal-case/)**：与驼峰命名类似，但第一个单词的首字母也大写。例如：`NumberOfGraduates`。

Python 代码风格指南（PEP 8）包含了各类对象名称的命名约定建议。对于变量，**PEP 8 推荐使用蛇形命名法（snake_case）**。

当需要多单词名称时，通常将形容词修饰语与名词结合使用：

```python
>>> initial_temperature = 25
>>> current_file = "marketing_personnel.csv"
>>> next_point = (2, 4)
```

通过组合形容词和名词，可以极大地提升代码可读性。另外要避免以 `my_` 开头的多单词名称（如 `my_file`、`my_color` 等），因为 `my_` 前缀并不能为命名提供任何有用的信息。

布尔标志变量也是多单词命名的典型用例：

```python
>>> is_authenticated = True
>>> has_permission = False
```

对于列表和字典，多数情况下应使用复数名词：

```python
>>> fruits = ["apple", "banana", "cherry"]
>>> colors = {
...     "Red": (255, 0, 0),
...     "Green": (0, 255, 0),
...     "Blue": (0, 0, 255),
...     "Yellow": (255, 255, 0),
...     "Black": (0, 0, 0),
...     "White": (255, 255, 255),
... }
```

使用复数名词清晰地传达了该变量是一个存储多个同类对象的容器。

在命名元组时，考虑到它们通常用于存储不同类型或含义的对象，因此可以使用单数名词：

```python
>>> color = (255, 0, 0)
>>> row = ("Jane", 25, "Python Dev", "Canada")
```

虽然这些元组存储了多个对象，但它们表示一个单一实体。第一个元组表示一种 RGB 颜色，第二个则表示数据库表中的一行记录。

#### 公开与非公开变量名

Python 中广泛使用的变量命名约定是：当你需要表明某个变量是 Python 中所谓的非公开（non-public）变量时，在变量名前加上**单下划线前缀**。非公开变量是不应在其所属模块之外使用的变量，仅供内部（internal）使用：

```python
# timeout.py

_timeout = 30

def get_timeout():
    return _timeout

def set_timeout(seconds):
    global _timeout
    _timeout = seconds
```

在该模块中，有一个名为 `_timeout` 的非公开变量，以及两个操作该变量的函数。该变量本身并不打算在包含模块的外部直接使用。

#### 受限与不推荐使用的名称

Python 保留了一小组被称为关键字（keywords）的词汇，它们是语言语法的一部分。可以通过以下代码获取 Python 的关键字列表：

```python
>>> import keyword
>>> keyword.kwlist
['False', 'None', 'True', 'and', 'as', 'assert', 'async', ..., 'yield']
```

大多数情况下，如果直接将这些词用作变量名，会导致语法错误：

```python
>>> class = "Business"
  File "<input>", line 1
    class = "Business"
          ^
SyntaxError: invalid syntax
```

如果确实需要使用与关键字重名的名称，可以遵循 PEP 8 的建议：**在名称末尾添加单下划线**：

```python
>>> class_ = "Business"
```

虽然这种约定可行，但有时更优雅的做法是换用更具体的名称：

```python
>>> passenger_class = "Business"
```

此时变量名更加具体且具描述性，可读性更佳。

此外还有软关键字（soft keywords），它们仅在特定语境下被视作关键字。例如 `match` 关键字仅在结构化模式匹配中才是关键字。因为 `match` 是软关键字，所以你仍可以将其用作变量名：

```python
>>> import re
>>> text = "Some text containing a number: 123"
>>> match = re.search("123", text)
>>> if match:
...     print("Found a match 😃")
... else:
...     print("No match found 😔")
...
Found a match 😃
```

另一个应避免的做法是使用内置名称（built-in names）来命名变量。例如，学习列表时写了如下代码：

```python
>>> list = [1, 2, 3, 4]
>>> list
[1, 2, 3, 4]
```

这会导致原始的内置 `list` 类型被遮蔽（shadowing），后续调用内置函数时将发生错误：

```python
>>> list(range(10))
Traceback (most recent call last):
  ...
TypeError: 'list' object is not callable
```

因此切忌使用内置名称作为变量名。

:::note[提示]

在交互式会话中运行以下代码可查看内置名称的完整列表：

```python
>>> import builtins
>>> dir(builtins)
['ArithmeticError', 'AssertionError', 'AttributeError', ..., 'tuple', 'type', 'vars', 'zip']
```

要检查变量名是否遮蔽了内置名称，可以使用 `"name" in dir(builtins)`。如果返回 `True`，建议换用其他名称。此规则对于第三方库中定义的对象名称同样适用。

:::

### 探索变量的核心特性

深入探究 Python 变量的底层工作原理时，会发现几个有趣的特性：

#### 变量持有对象的引用

使用赋值语句创建变量时底层到底发生了什么？在 Python 中，这个问题的答案与许多其他编程语言不同。

Python 是一门面向对象编程语言。Python 程序中的每块数据都是特定类型或类的对象。看下面的代码：

```python
>>> 300
300
```

当执行 `300` 语句时，Python 完成了以下操作：

1. 创建一个整型对象；
2. 赋予其值 300；
3. 将其显示在屏幕上。

使用内置的 [type()](https://realpython.com/python-built-in-functions/#creating-and-checking-types-type-isinstance-and-issubclass) 函数可以确认该整型对象的创建：

```python
>>> type(300)
<class 'int'>
```

Python 变量是一个**符号名称**，它**引用**或指向像 300 这样的对象。一旦将对象赋值给变量，就可以通过变量名来引用它，但数据本身始终包含在对象内部。

例如，考虑以下变量定义：

```python
>>> n = 300
```

该赋值语句创建了一个值为 300 的整型对象，并使变量 `n` 指向该对象。

在 Python 中，**变量并不存储对象本身，而是指向或引用对象**。每次在 Python 中创建对象时，该对象都会被分配一个唯一的标识编号，然后该编号与变量相关联。

内置的 [id()](https://realpython.com/python-built-in-functions/#knowing-an-objects-identity-id) 函数返回对象的唯一标识符（identity）：

```python
>>> n = 300
>>> id(n)
4399012816
```

在标准 Python 实现 CPython 中，对象的 identity 即为其内存地址。因此，CPython 变量中实际存储的是内存地址，通过该内存地址来访问内存中的具体对象。

你可以创建多个指向同一对象的变量（即持有相同内存地址的变量）：

```python
>>> m = n
>>> id(n) == id(m)
True
```

在此示例中，Python 没有创建新对象，而是创建了一个新的变量名（引用）`m`，指向 `n` 所指向的同一对象。

接着假设执行：

```python
>>> m = 400
```

此时 Python 会创建一个值为 400 的新整型对象，并将 `m` 改为指向它。

最后执行：

```python
>>> n = "foo"
```

Python 创建了一个值为 `"foo"` 的字符串对象，并让 `n` 引用该对象。

经过对 `n` 和 `m` 的重新赋值，原先的整型对象 300 不再有任何引用，变成了“孤儿对象”（orphaned object），你将无法再次访问它。

当一个对象的引用计数降为 0 时，该对象将无法再被访问，生命周期随之结束。Python 会回收分配的内存以便再利用。在编程术语中，此过程被称为垃圾回收（Garbage Collection）。

#### 变量具有动态类型

在许多静态类型语言中，变量在整个生命周期中被声明为具有固定的特定数据类型，赋予该变量的值必须属于该类型。

而 Python 变量并非如此。在 Python 中，你可以在不同时刻将不同数据类型的值赋给同一个变量：

```python
>>> value = "A string value"
>>> value
'A string value'
>>> # 之后重新赋值
>>> value = 23.5
>>> value
23.5
```

变量数据类型的变更可能引发运行时错误。例如，如果变量类型发生意外改变，可能导致类型相关的 Bug 甚至抛出异常：

```python
>>> value = "A string value"
>>> value.upper()
'A STRING VALUE'
>>> # 之后
>>> value = 23.5
>>> # 再次尝试使用 .upper()
>>> value.upper()
Traceback (most recent call last):
  ...
AttributeError: 'float' object has no attribute 'upper'
```

#### 变量可以使用类型提示

你可以使用类型提示（Type Hints）为变量添加显式的类型信息。语法如下：

```python
variable: data_type [= value]
```

方括号表示该部分是可选的。在 Python 中，确实可以声明一个变量而不为其赋值：

```python
>>> number: int
>>> number
Traceback (most recent call last):
  ...
NameError: name 'number' is not defined
```

第一行的变量声明是合法的 Python 语法，但并没有真正创建变量实体，因此访问时会引发 NameError。尽管如此，Python 已经在内部记录了该类型提示。

对于数字、字符串等基础数据类型，类型提示有时略显多余：

```python
>>> language: str = "Python"
>>> number: int = 42
>>> coefficient: float = 2.87
```

但对于列表、元组、字典和集合等容器类型，为其包含的数据提供类型提示就很有价值了。例如：

```python
>>> colors: dict[str, str] = {
...     "red": "#FF0000",
...     "green": "#00FF00",
...     "blue": "#0000FF",
...     "yellow": "#FFFF00",
...     "black": "#000000",
...     "white": "#FFFFFF",
... }
```

或者使用 RGB 元组的字典：

```python
>>> colors: dict[str, tuple[int, int, int]] = {
...     "Red": (255, 0, 0),
...     "Green": (0, 255, 0),
...     "Blue": (0, 0, 255),
...     "Yellow": (255, 255, 0),
...     "Black": (0, 0, 0),
...     "White": (255, 255, 255),
... }
```

在用空容器初始化变量时，类型提示尤其实用：

```python
>>> fruits: list[str] = []
>>> rows: list[tuple[str, int, str]] = []
```

这样即使容器为空，静态类型检查器（Linter）与读者也能明确容器内预期存放的对象类型。后续可以使用相关方法追加数据：

```python
>>> fruits.append("apple")
>>> fruits.append("orange")
>>> rows.append(("Jane", 25, "Python Dev"))
>>> rows.append(("John", 30, "Web Dev"))
```

### 创建变量的补充方式

除了最基本的赋值外，Python 还提供了多种创建变量的方式：

#### 并行赋值

Python 允许在单行代码中执行多次赋值，从而可以同时将相同的值赋给多个变量：

```python
>>> is_authenticated = is_active = is_admin = False
>>> is_authenticated
False
>>> is_active
False
>>> is_admin
False
```

相比逐行单独赋值，并行赋值更加简洁紧凑。

#### 可迭代对象解包

可迭代对象解包（Iterable Unpacking，也称元组解包）是 Python 的一大特色功能，它将可迭代对象中的各个值分配给一系列变量：

```python
>>> person = ("Jane", 25, "Python Dev")
>>> name, age, job = person
>>> name
'Jane'
>>> age
25
>>> job
'Python Dev'
```

解包的一个绝佳用例是在无需临时变量的情况下交换两个变量的值：

```python
>>> a = 5
>>> b = 10
>>> a, b = b, a
>>> a
10
>>> b
5
```

在此示例中，等号右侧是一个元组 `(b, a)`，通过解包直接完成了值交换。

#### 赋值表达式（海象运算符）

赋值表达式允许在条件语句或 `while` 循环中一步完成“求值并赋值”。例如传统的循环输入：

```python
>>> line = input("Type some text: ")
>>> while line != "stop":
...     print(line)
...     line = input("Type some text: ")
...
```

使用赋值表达式（海象运算符 `:=`）可以将其重写为：

```python
>>> while (line := input("Type some text: ")) != "stop":
...     print(line)
...
Type some text: Python
Python
Type some text: Walrus
Walrus
Type some text: stop
```

在 `(line := input("Type some text: "))` 中，创建了新变量 `line` 并将输入数据赋给它，同时将该表达式的值与 `"stop"` 进行比较，避免了重复调用 `input()`。

:::note[提示]

想要了解关于赋值表达式的更多详情，请参阅教程 [海象运算符：Python 的赋值表达式](https://realpython.com/python-walrus-operator/)。

:::

#### 模式匹配

结构化模式匹配（Structural pattern matching） 也能通过捕获模式来创建变量。当 `case` 子句匹配成功时，Python 会将捕获到的值绑定到新变量：

```python
>>> command = ("move", 10, 25)
>>> match command:
...     case ("move", x, y):
...         print(f"Moving to ({x}, {y})")
...
Moving to (10, 25)
```

在此示例中，`x` 和 `y` 在 `match` 语句之前并不存在，`case` 模式通过提取匹配元组的第 2 和第 3 个元素创建了它们。

### 理解变量作用域

作用域（Scope）决定了变量和名称在代码中的可见性与查找方式。变量的作用域取决于创建该变量的位置。

Python 中最多存在 4 种不同的作用域，通常用 **LEGB** 规则表示：

- **L**ocal（局部作用域）
- **E**nclosing（闭包/外层嵌套函数作用域）
- **G**lobal（全局作用域）
- **B**uilt-in（内置作用域）

:::note[提示]

想要深入了解 Python 作用域机制，请参阅：

#### 全局、局部与非局部变量

- **全局变量（Global variables）**：在模块级别创建的变量。在包含该变量的模块内部以及导入该模块的其他模块中均可见。在交互式 REPL 中，当前全局作用域定义在 `__main__` 模块中。
- **局部变量（Local variables）**：在函数内部定义的变量，仅在其所属函数内可见。函数执行完毕返回后，局部变量即销毁。
- **非局部变量（Non-local variables）**：在包含内部嵌套函数的外层函数中创建的变量。对于外层函数它是局部变量，但对于内部函数它属于非局部（non-local）变量，常用于闭包（closure）和装饰器（decorator）。

看下面的示例：

```python
# scopes.py

# 全局作用域
global_variable = "global"

def outer_func():
    # 闭包/非局部作用域
    nonlocal_variable = "nonlocal"

    def inner_func():
        # 局部作用域
        local_variable = "local"
        print(f"Hi from the '{local_variable}' scope!")
        print(f"Hi from the '{nonlocal_variable}' scope!")
        print(f"Hi from the '{global_variable}' scope!")

    inner_func()
```

调用 `outer_func()`：

```python
>>> from scopes import outer_func
>>> outer_func()
Hi from the 'local' scope!
Hi from the 'nonlocal' scope!
Hi from the 'global' scope!
```

:::note[提示]

内部函数可以直接**访问**全局变量和非局部变量。但若要在内部函数中**修改**它们，必须显式使用 [`global`](https://realpython.com/python-scope-legb-rule/#the-global-statement) 或 [`nonlocal`](https://realpython.com/python-scope-legb-rule/#the-nonlocal-statement) 语句声明。

:::

#### 类变量与实例变量（属性）

在面向对象编程中，在类中创建的变量称为属性（attributes）。分为类属性和实例属性：

- **类属性**：在类定义级别创建的变量，由该类及其所有实例共享。
- **实例属性**：绑定到特定对象实例上的变量，每个实例独立拥有。

```python
# employees.py

class Employee:
    count = 0  # 类属性

    def __init__(self, name, position, salary):
        self.name = name          # 实例属性
        self.position = position  # 实例属性
        self.salary = salary      # 实例属性
        Employee.count += 1

    def display_profile(self):
        print(f"Name: {self.name}")
        print(f"Position: {self.position}")
        print(f"Salary: ${self.salary}")
```

使用示例：

```python
>>> from employees import Employee
>>> jane = Employee("Jane Doe", "Software Engineer", 90000)
>>> john = Employee("John Doe", "Product Manager", 120000)
>>> jane.display_profile()
Name: Jane Doe
Position: Software Engineer
Salary: $90000
>>> john.display_profile()
Name: John Doe
Position: Product Manager
Salary: $120000
>>> f"Total employees: {Employee.count}"
'Total employees: 2'
```

:::note[提示]

不能通过 `self` 来直接修改类属性的值。例如执行 `self.count += 1` 会在当前实例上创建一个遮蔽类属性的同名实例属性，而不会更改 `Employee.count`。要修改类属性，必须通过类名操作（如 `Employee.count = 100`）或 `type(self).count`。

:::

#### 从作用域中删除变量

在 Python 中，可以使用 `del` 语句显式地从给定作用域中删除变量：

```python
>>> city = "New York"
>>> city
'New York'
>>> del city
>>> city
Traceback (most recent call last):
  ...
NameError: name 'city' is not defined
```

需要注意的是，`del` 删除的是对对象的**引用**，并不一定会立即释放内存。只有当对象的全部引用都归零时，Python 垃圾回收器才会回收该内存。

---

全局变量是指可以在代码的任何地方访问和修改的变量。在 Python 中，通常在模块级别定义全局变量。因此，包含它们的模块就是它们的作用域。

:::note
您也可以在函数内部定义全局变量，正如您将在“在函数内部创建全局变量”一节中了解到的那样。
:::

一旦定义了全局变量，您就可以在模块本身或代码中的其他模块内使用它。您也可以在函数中使用全局变量。然而，由于在函数中访问和修改全局变量之间存在差异，这些情况可能会变得有些令人困惑。

为了理解这些差异，请考虑 Python 可以在四种不同的作用域中查找变量：
* 存在于函数内部的局部（或函数级别）作用域。
* 存在于嵌套函数中的闭包（或非局部）作用域。
* 存在于模块级别的全局作用域。
* Python 内置名称的特殊作用域，即内置作用域。

举例来说，假设您位于一个内部函数中。在这种情况下，Python 可以在所有四个作用域中查找名称。

当您在该内部函数中访问一个变量时，Python 首先在该函数内部进行查找。如果该变量在那里不存在，那么 Python 将继续在外部函数的闭包作用域中查找。如果那里也没有定义该变量，那么 Python 将按顺序移动到全局作用域和内置作用域。如果 Python 找到了该变量，那么您将获得该返回值。否则，您将收到一个 `NameError`：

```python
>>> # Global scope
>>> def outer_func():
...     # Non-local scope
...     def inner_func():
...         # Local scope
...         print(some_variable)
...     inner_func()
...
>>> outer_func()
Traceback (most recent call last):
    ...
NameError: name 'some_variable' is not defined
>>> some_variable = "Hello from global scope!"
>>> outer_func()
Hello from global scope!

```

当您启动交互式会话时，它从全局作用域的模块级别开始。在这个例子中，您有 `outer_func()`，它将 `inner_func()` 定义为一个嵌套函数。从这个嵌套函数的角度来看，它自己的代码块代表局部作用域，而在调用 `inner_func()` 之前的 `outer_func()` 代码块代表非局部作用域。

如果您在没有在当前任何作用域中定义 `some_variable` 的情况下调用 `outer_func()`，那么您会得到一个 `NameError` 异常，因为该名称未定义。

如果您在全局作用域中定义了 `some_variable`，然后调用 `outer_func()`，那么您会在屏幕上看到 `Hello!`。在内部，Python 已经搜索了局部、非局部和全局作用域来找到 `some_variable` 并打印其内容。请注意，您可以在这三个作用域的任何一个中定义此变量，Python 都会找到它。

这种搜索机制使得从函数内部使用全局变量成为可能。然而，在利用这一特性的同时，您可能会面临一些问题。例如，访问变量是可行的，但直接修改变量却行不通：

```python
>>> number = 42
>>> def access_number():
...     return number
...
>>> access_number()
42
>>> def modify_number():
...     number = 7
...
>>> modify_number()
>>> number
42

```

`access_number()` 函数运行良好。它寻找 `number` 并在全局作用域中找到了它。相比之下，`modify_number()` 并没有按预期工作。为什么这个函数没有更新您的全局变量 `number` 的值呢？问题在于变量的作用域。您不能在像局部作用域这样的低级作用域中直接修改像全局作用域这样的高级作用域中的变量。

在内部，Python 假定在函数内直接分配的任何名称都是该函数的局部变量。因此，局部名称 `number` 遮蔽了它的全局同名变量。

在这个意义上，全局变量表现为只读名称。您可以访问它们的值，但不能修改它们。

:::note
关于在函数内部修改全局变量的讨论围绕的是赋值操作，而不是对可变对象的原地修改。您将在“理解可变性如何影响全局变量”一节中了解可变性对全局变量的影响。
:::

当您尝试在函数内部修改全局变量时，遇到 `UnboundLocalError` 异常是另一个常见问题。考虑以下尝试使用一些全局变量的演示函数：

```python
>>> a = 10
>>> b = 20
>>> c = 30
>>> def print_globals():
...     print(a, b, c)
...     c = 100
...     print(c)
...

```

在 `print_globals()` 内部，您首先打印全局变量 `a`、`b` 和 `c`。然后您直接更新 `c` 的值。最后，您打印更新后的 `c` 版本。您可能会期待以下输出：

```python
>>> # Expected output
>>> print_globals()
10 20 30
100

```

然而，这个输出永远不会出现在您的屏幕上。相反，您会收到一个可能会让您惊讶的错误：

```python
>>> print_globals()
Traceback (most recent call last):
    ...
UnboundLocalError: cannot access local variable 'c'
    where it is not associated with a value

```

问题在于赋值 `c = 100` 创建了一个新的局部变量，它覆盖了原始的全局变量 `c`。因此，您遇到了名称冲突。异常来自于第一次调用 `print()`，因为在那时，局部版本的 `c` 还未被定义。因此，您得到了 `UnboundLocalError`。

在实践中，这个问题最常出现在对全局变量进行增强赋值操作时：

```python
>>> counter = 0
>>> def increment():
...     counter += 1
...
>>> increment()
Traceback (most recent call last):
    ...
UnboundLocalError: cannot access local variable 'counter'
    where it is not associated with a value

```

在 Python 中，如果您的函数只是从全局作用域引用一个变量，那么该函数假定该变量是全局的。如果您在函数体内的任何地方为该变量名赋值，那么您就定义了一个与原始全局变量同名的新局部变量。

在函数内部，如果您在函数的任何地方定义了同名的局部变量，则无法直接访问全局变量。

如果想在函数内部修改全局变量，则需要显式告诉 Python 使用全局变量，而不是创建一个新的局部变量。为此，您可以使用以下方法之一：

1. `global` 关键字。
2. 内置的 `globals()` 函数。

在接下来的部分中，您将学习如何在代码中使用这两种工具来从函数内部更改全局变量。

### `global` 关键字

您已经了解到，从函数内部直接访问全局变量是完全可能的，除非包含它的函数中有同名的局部变量。除此之外，如果您还需要更改变量的值怎么办？在这种情况下，您可以使用 `global` 关键字来声明您想要引用该全局变量。

编写 `global` 语句的一般语法如下：

```python
global variable_0, variable_1, ..., variable_n

```

请注意，第一个变量是必需的，而其余的变量是可选的。为了说明如何使用此语句，回到 `counter` 和 `increment()` 示例。您可以通过执行类似以下操作来修复代码：

```python
>>> counter = 0
>>> def increment():
...     global counter
...     counter += 1
...
>>> increment()
>>> counter
1
>>> increment()
>>> counter
2

```

在这个新版本的 `increment()` 中，您使用 `global` 关键字来声明希望函数更新全局变量 `counter`。通过此语句，您现在能够修改函数内部 `counter` 的值，正如您在上面看到的。

:::note
Python 有一个 `nonlocal` 关键字，其工作原理类似于 `global`。它允许您在嵌套函数中使用非局部变量。非局部变量是指您在包含嵌套函数的函数中定义的变量。这些变量对内部或嵌套函数来说将是非局部的。
:::

需要注意的是，您必须在使用目标变量之前进行全局声明。否则，您将收到一个 `SyntaxError`：

```python
>>> counter = 0
>>> def increment():
...     counter += 1
...     global counter
...
SyntaxError: name 'counter' is assigned to before global declaration

```

在这个例子中，您试图在没有在 `increment()` 内将其声明为 `global` 的情况下递增 `counter`。因此，您得到了一个 `SyntaxError`。

`global` 语句告诉 Python 解释器，当您在这个函数中找到名称 `counter` 时，它指的是全局变量，所以不要创建局部变量。

总之，只有在您想在函数内重新分配全局变量时，才需要使用 `global` 关键字。如果您只需要从函数内部读取或访问全局变量的值，则不需要 `global` 关键字。

尽管 `global` 关键字的目的是在函数中处理全局变量，但这个关键字并不是您可用于此目的的唯一工具。您也可以使用内置的 `globals()` 函数。

### `globals()` 函数

内置的 `globals()` 函数允许您访问全局作用域的名称表，这是一个可写字典，包含您当前的全局名称及其对应的值。您可以使用此函数从函数内部访问或修改全局变量的值。

例如，当您有与目标全局变量同名的局部变量，并且仍然需要在函数内部使用全局变量时，此函数非常有用：

```python
>>> a = 10
>>> b = 20
>>> c = 30
>>> def print_globals():
...     print(a, b, globals()["c"])
...     c = 100
...     print(c)
...
>>> print_globals()
10 20 30
100
>>> c
30

```

在这个 `print_globals()` 的新实现中，`c` 指的是变量的局部版本，而 `globals()["c"]` 指的是全局版本。

由于 `globals()` 返回一个字典，因此您可以像访问常规字典的键一样访问其键。请注意，您需要使用变量的名称作为字符串来访问 `globals()` 中的对应键。

`globals()` 返回的名称字典是可变的，这意味着您可以利用该字典更改现有全局变量的值。在最后一个示例中，您可以看到全局变量 `c` 仍然持有相同的值。

这是另一个版本的 `increment()`。它稍微有点难读，但它有效：

```python
>>> counter = 0
>>> def increment():
...     globals()["counter"] += 1
...
>>> increment()
>>> counter
1
>>> increment()
>>> counter
2

```

在这个例子中，您使用 `globals()` 而不是 `global` 关键字实现了 `increment()`。这两种实现的工作方式相同，您可以通过连续调用函数后 `counter` 的内容来确认这一点。

请注意，使用 `globals()` 来访问和更新全局变量可能会使您的代码难以阅读和理解，特别是对于大型程序。一般情况下，除非您有与目标全局变量同名的局部变量，否则最好使用 `global` 关键字。

### 理解可变性如何影响全局变量

Python 拥有可变和不可变的数据类型。可变类型（例如列表和字典）允许您就地更改或变异它们的值。相比之下，不可变类型（如数字、字符串和元组）不允许您就地修改它们的值。

为了快速说明可变性和不可变性在 Python 中是如何工作的，考虑以下示例，您就地变异一个列表，更改其元素或项目的值：

```python
>>> numbers = [1, 2, 3]
>>> id(numbers)
4390329600
>>> numbers[0] = 10
>>> numbers[1] = 20
>>> numbers[2] = 30
>>> numbers
[10, 20, 30]
>>> id(numbers)
4390329600

```

在这个例子中，您变异了 `numbers` 的值。由于 Python 列表是可变对象，这种变异不会改变您列表对象的标识，仅改变其值。在进行变异前后，您可以通过比较内置 `id()` 函数的输出来确认这一点。

现在，如果您尝试在诸如元组这样的不可变类型上执行类似操作会发生什么？在这个代码示例中，您尝试了一下：

```python
>>> letters = ("a", "b", "c", "d")
>>> letters[0] = "aa"
Traceback (most recent call last):
    ...
TypeError: 'tuple' object does not support item assignment

```

这里，您使用元组来存储字母。Python 元组是不可变的，因此您不能像对数字列表那样就地更改它们的项目。如果您尝试这样做，就会得到一个 `TypeError`。

当在函数内部使用指向可变对象的全局变量时，您会注意到可以直接就地更改它们的值。

例如，假设您正在创建一个 REST API 应用程序。为了方便起见，您使用一个全局字典跨应用代码共享 API 配置。同样为了方便，您编写了一个允许您更新配置参数的简短函数：

```python
>>> config = {
...     "base_url": "[https://example.com/api](https://example.com/api)",
...     "timeout": 3,
... }
>>> def update_config(**kwargs):
...     for key, value in kwargs.items():
...         if key in {"api_key", "base_url", "timeout"}:
...             config[key] = value
...         else:
...             raise KeyError(key)
...
>>> update_config(api_key="111222333")
>>> config
{
    'api_key': '111222333',
    'base_url': '[https://example.com/api](https://example.com/api)',
    'timeout': 3
}
>>> update_config(timeout=5)
>>> config
{
    'api_key': '111222333',
    'base_url': '[https://example.com/api](https://example.com/api)',
    'timeout': 5
}

```

在此示例中，`update_config()` 函数允许您更新应用程序的配置参数。该函数接受仅限关键字的参数。每个参数必须是具有相应值的有效配置参数。在条件语句中，您使用 `in` 运算符检查此条件。如果参数无效，那么函数会引发 `KeyError`。

因为 Python 字典是可变数据类型，所以无需使用 `global` 或 `globals()` 即可在 `update_config()` 内部就地更改 `config` 的值。如果它们是有效的配置参数，您甚至可以添加新的键值对。例如，对 `update_config()` 的第一次调用添加了 `api_key` 参数，而第二次调用更新了 `timeout` 参数。

需要注意的是，配置和设置通常是应用程序或系统全局状态的重要组成部分。在系统运行时更改配置会变异其全局状态。您应仅在非常小心的情况下进行此类更改。某些应用和软件系统在您更改其某些配置参数后要求重新启动或重新加载。这是处理这类状态变异的好方法。

### 在函数内部创建全局变量

正如您已经了解到的，您可以使用 `global` 关键字或内置的 `globals()` 函数在函数内部访问和修改全局变量。真正有趣且可能令人惊讶的是，您还可以使用这些工具在函数内部创建全局变量。

:::warning
虽然您可以使用 `global` 关键字或 `globals()` 函数在函数内部创建全局变量，但这是非常罕见的，而且不是最佳实践。它会使您的代码难以理解和维护。
:::

最好在任何函数外部的模块级别定义全局变量。这样，它们的作用域就很清楚了，而且如果您在调用定义函数之前使用该变量，就不会有遇到 `NameError` 的风险。

在这个例子中，您使用 `global` 关键字在函数内部创建了一个全局变量：

```python
>>> def set_global_variable():
...     global number
...     number = 7
...
>>> set_global_variable()
>>> number
7

```

在这里，`set_global_variable()` 函数使用 `global` 关键字将 `number` 定义为全局变量。当您调用函数时，`number` 被定义，并且它的值被设置为 7。在调用之后，您可以从程序中的任何其他位置访问 `number`。

您还可以使用 `globals()` 函数在函数内部定义新的全局变量。该工具为您提供了额外的灵活性，使您能够动态地创建全局变量：

```python
>>> def dynamic_global_variable(name, value):
...     globals()[name] = value
...
>>> dynamic_global_variable("number", 42)
>>> number
42

```

在此示例中，`dynamic_global_variable()` 函数使用 `globals()` 函数通过字符串名称和值定义新的全局变量。对函数的调用创建了一个名为 `number` 的新全局变量，其值为 42。

为了提供一个更现实的示例，假设您有一个 JSON 格式的配置文件。您想要处理该文件并将所有配置参数直接加载到您的全局命名空间中，以便您可以在代码的其他部分将这些参数用作全局变量。

您的 `config.json` 文件可能如下所示：

```json
{
    "database": {
      "host": "localhost",
      "port": 5432,
      "name": "database.db",
      "user": "username",
      "password": "secret"
    },
    "api_key": "111222333",
    "base_url": "[https://example.com/api](https://example.com/api)",
    "timeout": 60
}

```

该文件定义了一个 `"database"` 键，其值是一个包含键和值的字典。您将把此字典用作应用程序数据库的初始设置。该文件还定义了用于连接 API 的 API 密钥、基础 URL 和超时。

以下代码负责加载 JSON 文件并为您创建所需的一组全局变量：

```python
>>> import json
>>> def set_config_key(key, value):
...     globals()[key] = value
...
>>> with open("config.json") as json_config:
...     for key, value in json.load(json_config).items():
...         set_config_key(key, value)
...
>>> database
{
    'host': 'localhost',

    'password': 'secret'
}
>>> api_key

```

在这个代码片段中，您定义了 `set_config_key()`，它以 `key` 和 `value` 作为参数。然后您使用 `globals()`，以 `key` 作为变量名，以 `value` 作为其值来创建一个全局变量。

在 `with` 语句中，您打开配置文件进行读取，并将文件对象分配给 `json_config` 变量。然后您使用一个 `for` 循环来处理加载的配置，并为每个键值对创建新的全局变量。

完成此过程后，您可以将代码中所有配置参数作为全局变量进行访问。

尽管在 Python 中使用 `global` 关键字或 `globals()` 函数在函数中定义全局变量是完全可能的，但这并不是最佳实践。以此方式定义全局变量时必须小心。这些变量将变得对整个程序可用，因此代码的其他部分可以修改它们。正因为如此，您最终可能会得到难以理解、测试、维护和调试的代码。

也许您注意到了某种模式。在函数中使用和定义全局变量的方法有很多，但这是否意味着您应该这么做？在下一部分中，您将探讨这个问题。

### 决定何时使用全局变量

在您的编程之旅中，您会发现某些情况下使用全局变量可能是合适的甚至是必要的。例如，您可能会使用全局变量来处理：

* 配置和设置：如果您有一些适用于整个程序的设置，那么使用全局变量可能是一个快速的解决方案，它将允许您从代码的任何地方访问这些设置。
* 小型实用脚本：如果您正在编写小型脚本来自动化部分工作流程或完成微小的任务，那么使用全局变量可以帮助您更快地运行，并阻止您过度设计解决方案。
* 缓存数据：如果您出于性能原因需要缓存数据，那么您可以利用全局变量来存储缓存的数据。

需要注意的是，您应该谨慎地并且仅在绝对必要时使用全局变量。如果决定在代码中使用全局变量，请务必记录其使用情况，特别要注意为什么依赖它们。

在实践中，在代码中使用全局变量可能会有一些缺点。例如，全局变量可能：

* 使跟踪变量的更改变得困难，因为您可以从代码的任何位置更改变量。
* 产生不必要的副作用，因为对全局变量的更改可能会影响代码其他部分的行为。
* 使代码难以测试和调试，因为函数的行为和结果将取决于全局变量的当前值。
* 影响代码的可重用性，因为依赖全局变量的函数与这些变量紧密耦合。
* 导致命名冲突，因为您可能会在代码的不同部分意外地重用全局名称，从而导致意外结果。
* 破坏封装性，因为全局变量在代码的不同部分之间引入了隐藏的依赖关系。
* 使代码难以重构，因为代码某一部分的更改可能会影响其他部分。

虽然您可以利用全局变量解决特定问题，但尽量减少在代码中的使用会更好。如果仍然需要使用它们，可以将它们作为常量，以避免它们的部分缺点。这是因为使用全局变量的大多数问题源于在代码执行期间更改它们的值。

在接下来的几节中，您将学习一些常用的策略和技术，以避免在函数中使用全局变量。

### 在代码和函数中避免使用全局变量

正如您在上一节中所了解的，在函数和代码中依赖全局变量可能会导致一些不良影响。这些变量可能会使代码更难理解、测试和调试。它们还可能导致难以维护和重用的代码。因此，您必须小心控制地使用全局变量。

幸运的是，您可以采用一些巧妙的策略来减少对全局变量的需求。

#### 使用全局常量

也许避免全局变量最直观的策略就是使用全局常量。与变量不同，常量在代码执行期间不得更改其值。因此，它们促进了对全局名称的安全使用。

:::tip
Python 不支持严格常量或不可重新赋值的名称。要在 Python 中定义常量，应使用大写字母加下划线。然而，这只是命名约定，并不能阻止开发人员为您的常量分配新值。所以，您必须小心，千万不要编写更改常量值的代码。
:::

为了说明如何使用常量代替全局变量，假设您有一些常规配置参数，并希望可以从程序的所有部分访问它们。在这种情况下，可以使用全局常量。通常，在模块顶部导入之后定义常量。

下面是一些 Python 常量的示例：

```python
API_KEY = "111222333"
BASE_URL = "[https://example.com/api](https://example.com/api)"
TIMEOUT = 3

```

您可以使用常量存储在程序执行期间不会改变的值。常量可帮助防止意外修改值。它们还提高了代码的可读性和可维护性。

一旦定义了常量，即可在整个代码的函数中访问它们。您只需确保保持它们不变即可。例如，以下函数从 NASA 的主 API 页面加载图像：

```python title="nasa.py"
import webbrowser
import requests

API_KEY = "DEMO_KEY"
BASE_URL = "[https://api.nasa.gov/planetary](https://api.nasa.gov/planetary)"
TIMEOUT = 3

def load_earth_image(date):
    endpoint = f"{BASE_URL}/apod"
    try:
        response = requests.get(
            endpoint,
            params={
                "api_key": API_KEY,
                "date": date,
            },
            timeout=TIMEOUT,
        )
    except requests.exceptions.RequestException as e:
        print(f"Error connecting to API: {e}")
        return

    try:
        url = response.json()["url"]
    except KeyError:
        print(f"No image available on {date}")
        return

    webbrowser.open(url)

```

在此示例中，您从 Python 标准库中导入了 `webbrowser`。此模块可让您在其默认浏览器中快速打开 URL。然后导入 `requests` 库以向目标 REST API 发出 HTTP 请求。

在 `load_earth_image()` 中，您可以直接访问三个全局常量，就像处理 Python 中的任何全局变量一样。但是，您在函数内部不更改任何常量的值。

现在，您也可以在其他相关的函数中重复使用这些常量。以这种方式使用常量允许您改善代码的可读性和可维护性。此外，由于它们是常数，当您调试或测试代码时，您不必跟踪其当前值。您始终会知道它们的值。

要测试以上示例，请继续并运行以下代码：

```python
>>> from nasa import load_earth_image
>>> load_earth_image("2024-11-21")

```

对 `load_earth_image()` 的调用将为您获取 NASA 为 2024 年 11 月 21 日准备的图像。图像将在您的默认浏览器中打开。您可以尝试使用其他日期获取自己的图像。

#### 在函数中接收参数并返回值

编写采用参数并返回值的函数，而不是依赖全局变量，这是在您的代码中避免使用全局变量的另一个好策略。这类函数被称为纯函数，并且是函数式编程的基础，该编程泛型目前十分流行。

纯函数通常与代码的其他部分完全分离。更重要的是，它们不会产生任何副作用，例如更改全局变量的状态。这些功能使它们更易于重用且更容易理解、调试、测试和维护。

例如，以下是不在函数内部使用全局变量的老朋友 `increment()` 的新实现。在此处，函数仅接受一个值作为参数，并将其增加 1 返回：

```python
>>> def increment(value=0):
...     return value + 1
...
>>> counter = increment()
>>> counter
1
>>> counter = increment(counter)
>>> counter
2
>>> counter = increment(counter)
>>> counter
3

```

`increment()` 的这个新版本不再依赖全局变量中的外部值。因此，其结果仅取决于它的输入参数。无论何时，只要参数相同，此函数总是返回相同的结果，这就使得这个函数更易于测试、理解和调试。

该函数与程序的任何其他部分完全解耦，以至于您甚至可以在不同的程序中重用它。

在这个例子中，您仅在全局作用域内改变 `counter` 变量。您不执行跨作用域突变，所以使代码更安全且更容易理解。

#### 使用类、方法和属性

有时候您可能具有一个或多个作用在或伴随一些全局变量运行的函数。在这些情况下，您能考虑编写一个将函数转化为方法并将全局变量转化为实例属性的类。

例如，假设您正在编写一款应用程序来管理自己的银行账户。您通过创建一系列处理账户余额的函数来开始：

```python title="account_global.py"
balance = 0

def deposit(amount):
    global balance
    balance += amount
    print(f"Successful deposit: +${amount:,.2f}")

def withdraw(amount):
    global balance
    if balance - amount > 0:
        balance -= amount
        print(f"Successful withdrawal: -${amount:,.2f}")
    else:
        print("Not enough funds for this transaction")

def get_balance():
    return balance

def main():
    while True:
        operation = input(
            "What would you like to do?\n"
            " d) deposit  "
            " w) withdraw  "
            " b) balance  "
            " q) quit\n"
            "> "
        )
        if operation in "dD":
            amount = float(input("Enter the deposit amount: "))
            deposit(amount)
        elif operation in "wW":
            amount = float(input("Enter the withdrawal amount: "))
            withdraw(amount)
        elif operation in "bB":
            print(f"Current balance: ${get_balance():,.2f}")
        elif operation in "qQ":
            print("Goodbye!")
            break
        else:
            print("Invalid operation. Please try again.")

main()

```

在这段代码中，您依靠一个全局变量存储您的银行账户的余额。您具有三种提供共同操作账户余额功能的函数。您可以存钱、提款，并且检查您账户的现有余额。

`main()` 函数定义了一条向您显示文本用户界面 (TUI) 的 `while` 循环。通过此界面，您告诉该应用将想要进行的操作执行在自己的账户中。

以下是此应用在运行时的展示：

```bash

> d

What would you like to do?
 d) deposit   w) withdraw   b) balance   q) quit
> w
Enter the withdrawal amount: 2380
Successful withdrawal: -$2,380.00
What would you like to do?
 d) deposit   w) withdraw   b) balance   q) quit
> b

What would you like to do?
 d) deposit   w) withdraw   b) balance   q) quit
> q

```

太棒了！该应用程序按预期工作。它允许您存款、提取资金并检查您的当前余额。现在，假设您不喜欢过度依赖全局变量，并且您决定使用类来重构应用程序。为此，您需要执行以下步骤：

1. 用合适的名称定义一个类。`Account` 适用于此示例。
2. 将全局变量移入该类，将它们转换为实例属性。
3. 将函数作为实例方法移入该类。

这是重构的代码：

```python title="account_class.py"
class Account:
    def __init__(self, balance=0):
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount
        print(f"Successful deposit: +${amount:,.2f}")

    def withdraw(self, amount):
        if self.balance - amount > 0:
            self.balance -= amount
            print(f"Successful withdrawal: -${amount:,.2f}")
        else:
            print("Not enough funds for this transaction")

def main():
    account = Account()
    while True:
        operation = input(
            "What would you like to do?\n"
            " d) deposit  "
            " w) withdraw  "
            " b) balance  "
            " q) quit\n"
            "> "
        )
        if operation in "dD":
            amount = float(input("Enter the deposit amount: "))
            account.deposit(amount)
        elif operation in "wW":
            amount = float(input("Enter the withdrawal amount: "))
            account.withdraw(amount)
        elif operation in "bB":
            print(f"Current balance: ${account.balance:,.2f}")
        elif operation in "qQ":
            print("Goodbye!")
            break
        else:
            print("Invalid operation. Please try again.")

main()

```

在会计程序的新版本中，您定义了一个名为 `Account` 的类。该类具有一个用于存储账户余额的实例属性。该属性曾是您的老全局变量 `balance`。

您还把 `deposit()` 和 `withdraw()` 方法转变成了包含当前实例 `self` 作为第一参数的实例方法。最后，在循环的内部，您实例化了 `Account` 类并在实例里使用该类调用它的方法从而使该程序运转时的情况犹如上代版本一样。

注意，在这个实现中，您没有 `.get_balance()` 方法。所以，要获得账户存款情况可以依靠其属性 `.balance` 实现。

## 理解常量与变量

变量和常量是计算机编程中两个历史悠久且基础的概念。大多数编程语言都使用这些概念来高效、合乎逻辑地处理和操作数据。

在你编写的每一个项目、应用程序、库或其他代码中，几乎都会出现变量和常量。问题是：在实际应用中，究竟什么是变量和常量？

### 什么是变量

在数学中，变量被定义为指代随时间变化的值或数量的符号。在编程中，变量同样是一个符号或名称，通常关联到一个包含值、对象或数据片段的内存地址。与数学中一样，编程中变量的内容在定义它的代码执行期间是可以改变的。

变量通常具有描述性名称，该名称在某种程度上与目标值或对象相关联。此目标值可以是任何数据类型。因此，你可以使用变量来表示数字、字符串、序列、自定义对象等。

你可以对变量执行两个主要操作：

1. 访问其值
2. 为其赋新值

在大多数编程语言中，你只需在代码中引用变量的名称即可访问与该变量关联的值。要为给定的变量赋新值，你需要使用赋值语句，该语句通常由变量名、赋值运算符和所需的值组成。

在实践中，你会发现许多可以表示为变量的大量数据、数值和对象。几个例子包括温度、速度、时间、长度。你可以当作变量处理的其他数据示例还包括：Web 应用程序中的注册用户数、视频游戏中活跃角色的数量、跑步者跑过的英里数。

### 什么是常量

数学中也有常量的概念。该术语指从不改变的值或数量。在编程中，常量是指在程序执行期间永不改变的值所关联的名称。

就像变量一样，编程常量由两部分组成：名称和关联值。名称将清楚地描述该常量的用途。值则是常量本身的具体表现。

与变量一样，给定常量关联的值可以是任何数据类型。因此，你可以定义整型常量、浮点型常量、字符型常量、字符串型常量等。

定义常量后，它只允许你对其执行单一操作。你只能访问常量的值，而不能随时间更改它。这与变量不同，变量允许你访问其值，但也可以重新赋值。

你将使用常量来表示不会改变的值。在日常编程中，你会发现很多这样的值。几个例子包括光速、一小时内的分钟数、项目根文件夹的名称。

### 为什么使用常量

在大多数编程语言中，当你凌晨两点还在写代码时，常量可以保护你免受意外更改代码中某些值的困扰，从而避免引发意外且难以调试的错误。常量还可以帮助你使代码更具可读性和可维护性。

与直接在代码中使用值相比，使用常量的一些优势包括：

| 优势 | 描述 |
| --- | --- |
| **提高可读性** | 在整个程序中代表给定值的描述性名称，总是比单纯的原始值更具可读性和明确性。例如，阅读和理解名为 `MAX_SPEED` 的常量，比直接看具体的速度值要容易得多。 |
| **清晰传达意图** | 大多数人会假设 `3.14` 可能指圆周率常量。然而，使用 `Pi`、`pi` 或 `PI` 这样的名称比直接使用该值能更清晰地传达你的意图。这种做法可以让其他开发者快速、准确地理解你的代码。 |
| **更好的可维护性** | 常量使你能够在整个代码中使用相同的名称来标识相同的值。如果你需要更新常量的值，则不必更改该值的所有实例。你只需要在一个地方进行更改，即常量定义处。这提高了代码的可维护性。 |
| **降低出错风险** | 在整个程序中代表给定值的常量，比多次显式出现该值的代码更不容易出错。假设你根据目标计算需要使用不同精度的圆周率（Pi）。你在每次计算中都显式使用了所需精度的值。如果你需要在一组计算中更改精度，替换这些值可能会出错，因为你最终可能会更改错误的值。为不同的精度级别创建不同的常量并在单个地方更改代码会更安全。 |
| **减少调试需求** | 常量在程序的整个生命周期中保持不变。因为它们始终具有相同的值，所以它们不应该引发错误和 bug。这个特性在小型项目中可能不是必需的，但在包含多名开发人员的大型项目中至关重要。开发人员无需花时间去排查任何常量的当前值。 |
| **线程安全的数据存储** | 常量只能被访问，不能被写入。这个特性使它们成为线程安全的对象，这意味着多个线程可以同时使用常量，而不会有破坏或丢失底层数据的风险。 |

正如你从这个表格中所学到的，常量是编程中一个重要的概念，这是有充分理由的。它们可以让你的生活更轻松，让你的代码更可靠、更具可维护性和可读性。现在，什么时候应该使用常量呢？

### 何时使用常量

生活（尤其是科学）充满了常量值或从不改变的值的例子。几个例子包括：

* `3.141592653589793`：由 $\pi$ 表示的常量，在英文中拼写为 Pi，代表圆的周长与直径之比。
* `2.718281828459045`：由 $e$ 表示并被称为欧拉数的常量，它与自然对数和复利密切相关。
* `3,600`：一小时中的秒数，在大多数应用中被认为是常数，尽管有时会添加闰秒来解释地球自转速度的变化。
* `-273.15`：表示摄氏温度绝对零度的常量，等于开尔文温标上的 0 开尔文。

以上所有示例都是人们在生活和科学中常用的常量值。在编程中，你会经常发现自己需要处理这些以及许多其他可以被视为常量的类似值。

总而言之，使用常量来表示量、数值、对象、参数或任何在生命周期内理应保持不变的数据。

## 在 Python 中定义你自己的常量

到目前为止，你已经了解了常量作为生活、科学和编程中通用概念的定义。现在是时候了解 Python 是如何处理常量的了。首先，你应该知道 Python 没有用于定义常量的专用语法。

换句话说，在严格意义上，Python 没有常量。它只有变量，这主要是由其动态特性决定的。因此，要在 Python 中使用常量，你需要定义一个永不改变的变量，并通过避免对变量本身执行赋值操作来维持这种行为。

> **注意**：在本节中，你将重点学习如何定义自己的常量。不过，Python 中内置了一些常量。你稍后会学到它们。

```python
ALLOWED_BUILTINS = ("sum", "max", "min", "abs")
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    ...]

```

请注意，你创建这些常量的方式与创建变量完全相同。你使用了描述性名称、赋值运算符 (`=`) 以及常量的具体值。

通过仅使用大写字母，你在传达这样一种意图：当前的名称旨在被当作常量对待——或者更准确地说，是被当作一个永不改变的变量对待。因此，其他 Python 开发者会知道这一点，并且希望不会对该变量执行任何赋值操作。

> **注意**：再次强调，Python 不支持常量或不可重新赋值的名称。使用大写字母只是一种规范，它并不能阻止开发人员为你的常量赋予新值。因此，任何编写你代码的程序员都需要格外小心，绝不编写改变常量值的代码。请记住这条规则，因为你也需要遵守它。

由于 Python 常量本质上就是变量，因此两者遵循相似的命名规则，唯一的区别在于常量仅使用大写字母。基于这一理念，常量的名称可以：

* 具有任意长度
* 由大写字母（A–Z）组成
* 包含数字（0–9），但不能作为首个字符
* 使用下划线字符（`_`）来分隔单词，或将其作为首个字符

使用大写字母会使你的常量从变量中脱颖而出。通过这种方式，其他开发人员能够明确地识别出它们的用途。

作为一般的命名建议，在定义常量时应避免使用缩写的名称。常量名称的目的是阐明常量值的含义，以便你以后可以重复使用它。这个目标需要具有描述性的名称。应避免使用单字母名称、不常见的缩写以及诸如 `NUMBER` 或 `MAGNITUDE` 这样的通用名称。

推荐的做法是在任何 `.py` 文件的顶部、紧跟在所有导入语句（import statements）之后定义常量。这样一来，阅读你代码的人就会立即明白常量的用途和预期的处理方式。

### 模块级双下划线常量

模块级双下划线名称（dunder names）是指以双下划线开头和结尾的特殊名称。一些例子包括 `__all__`、`__author__` 和 `__version__` 等名称。在 Python 项目中，这些名称通常被视为常量。

> **注意**：在 Python 中，dunder 名称是具有特殊含义的名称。它以双下划线开头和结尾，“dunder”这个词是“double underscore（双下划线）”的混成词。

根据 Python 的代码风格指南 PEP 8，模块级双下划线名称应该出现在模块的文档字符串（docstring）之后、除了 `__future__` 导入之外的任何导入语句之前。

这是一个包含一堆双下划线名称的示例模块：

文件名：`greeting.py`

```python
"""This module defines some module-level dunder names."""
from __future__ import barry_as_FLUFL

__all__ = ["greet"]
__author__ = "Real Python"
__version__ = "0.1.0"

import sys

def greet(name="World"):
    print(f"Hello, {name}!")
    print(f"Greetings from version: {__version__}!")
    print(f"Yours, {__author__}!")

```

在这个例子中，`__all__` 在最前面定义了当你在代码中使用 `from module import *` 导入结构时 Python 将导入的名称列表。在这种情况下，使用通配符导入（wildcard import）导入 `greeting` 的人将只能取回 `greet()` 函数。他们将无法访问 `__author__`、`__version__` 以及未在 `__all__` 中列出的其他名称。

> **注意**：`from module import *` 结构允许你一次性导入给定模块中定义的所有名称。`__all__` 属性将导入的名称限制为仅底层列表中的那些。

Python 社区强烈反对这种通常被称为通配符导入的导入结构，因为它往往会用你可能不会在代码中使用的名称来弄乱当前的命名空间。

相比之下，`__author__` 和 `__version__` 对代码的作者和用户有意义，而不是对代码本身的逻辑有意义。由于在程序执行期间不应允许任何代码更改作者或版本，因此这些名称应被视为常量。

请注意，`greet()` 函数确实访问了这些双下划线名称，但并没有改变它们。`greet()` 在实践中的工作方式如下：

```pycon
>>> from greeting import *
>>> greet()
Hello, World!
Greetings from version: 0.1.0!
Yours, Real Python!

```

一般来说，没有什么硬性规则可以阻止你定义自己的模块级双下划线名称。但是，Python 官方文档强烈警告：不要使用社区普遍接受和使用之外的双下划线名称。核心开发人员未来可能会在没有任何警告的情况下向该语言引入新的双下划线名称。

### 将常量付诸实践

到目前为止，你已经了解了常量及其在编程中的角色和重要性。你还了解到 Python 不支持严格意义上的常量。这就是为什么你可以将常量视为永不改变的变量。

在接下来的部分中，你将编写代码示例，体会常量在日常编码旅程中的巨大价值。

#### 替换“魔法数字”以提高可读性

在编程中，“魔法数字”（magic number）一词指的是任何直接出现在代码中且没有任何解释的数字。它是一个毫无预兆冒出来的价值，让你的代码变得神秘且难以理解。魔法数字还会降低程序的可读性，并使维护和更新变得更加困难。

例如，假设你有以下函数：

```python
def compute_net_salary(hours):
    return hours * 35 * (1 - (0.04 + 0.1))

```

你能一眼看出这个计算中每个数字的含义吗？大概不能。这个函数中的不同数字都是魔法数字，因为你无法从数字本身可靠地推断出它们的含义。

来看看这个函数的重构版本：

```python
HOURLY_SALARY = 35
SOCIAL_SECURITY_TAX_RATE = 0.04
FEDERAL_TAX_RATE = 0.10

def compute_net_salary(hours):
    return (
        hours * HOURLY_SALARY * (1 - (SOCIAL_SECURITY_TAX_RATE + FEDERAL_TAX_RATE))
    )

```

通过这些微小的更新，你的函数现在读起来顺畅多了。你和任何阅读你代码的其他开发人员一定能看出这个函数是做什么的，因为你用命名恰当的常量替换了原有的魔法数字。每个常量的名字都清晰地解释了它对应的含义。

每当你发现自己在代码中使用魔法数字时，都要花时间用常量将其替换。这个常量的名称必须具有描述性，并且要明确解释目标魔法数字的含义。这种做法将自动提高代码的可读性。

#### 重用对象以提高可维护性

常量的另一个日常用例是，当某个给定的值在代码的不同部分中反复出现时。如果你在每个需要的地方都将具体的值插入代码中，那么如果出于某种原因你需要更改该值，你就会遇到麻烦。在这种情况下，你需要在每个地方都修改该值。

同时在多个地方更改目标值很容易出错。即使你依赖编辑器的“查找和替换”功能，也可能会遗漏某些未更改的值实例，这可能会在以后导致意想不到的 bug 和诡异的行为。

为了防止这些令人烦恼的问题，你可以用命名恰当的常量来替换该值。这将允许你设置一次该值，并在根据需要所需的任意位置重复使用它。如果你需要更改常量的值，那么你只需在一个地方进行更改：即常量定义处。

例如，假设你正在编写一个 `Circle`（圆）类，并且你需要计算圆的面积、周长等的方法。编写了几分钟代码后，你得到了以下类：

文件名：`circle.py`

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius**2

    def perimeter(self):
        return 2 * 3.14 * self.radius

    def projected_volume(self):
        return 4/3 * 3.14 * self.radius**3

    def __repr__(self):
        return f"{self.__class__.__name__}(radius={self.radius})"

```

这个例子揭示了圆周率的近似值 (`3.14`) 是如何作为一个魔法数字写在 `Circle` 类的几个方法中的。为什么这种做法有问题？假设你需要提高圆周率的精度。那么你将不得不手动更改至少三个不同地方的值，这既繁琐又容易出错，使得你的代码难以维护。

> **注意**：通常，你不需要自己定义圆周率。Python 附带了一些内置常量，包括圆周率。你稍后将看到如何利用它。

使用命名常量来存储圆周率的值是解决这些问题的一种极佳方法。以下是上述代码的增强版本：

文件名：`circle.py`

```python
PI = 3.14

class Circle:
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return PI * self.radius**2

    def perimeter(self):
        return 2 * PI * self.radius

    def projected_volume(self):
        return 4/3 * PI * self.radius**3

    def __repr__(self):
        return f"{self.__class__.__name__}(radius={self.radius})"

```

这个版本的 `Circle` 使用全局常量 `PI` 替换了魔法数字。与原始代码相比，这段代码有几个优点。如果你需要提高圆周率的精度，那么你只需要在文件开头更新 `PI` 常量的值。此更新将立即反映在其余代码中，而无需你采取任何额外的操作。

> **注意**：常量在代码执行期间不应更改。然而，在开发过程中，你可以根据需要更改和调整你的常量。在 `Circle` 类中更新圆周率的精度，很好地说明了为什么你可能需要在代码开发过程中更改常量的值。

另一个优点是，现在你的代码更具可读性，也更容易理解。常量的名称是不言自明的，并且反映了公认的数学术语。

正如你在上面的示例中所做的那样，声明一次常量然后多次重用它，代表了可维护性的显著提升。如果你必须更新常量的值，那么你只需在一个地方而不是多个地方进行更新，这意味着更少的工作量和更低的错误风险。

#### 提供默认参数值

在 Python 中，使用命名常量为函数、方法和类提供默认参数值是另一种常见的做法。在 Python 标准库中有很多这种做法的示例。

例如，`zipfile` 模块提供了用于创建、读取、写入、追加和列出 ZIP 文件的工具。该模块中最相关的类是 `ZipFile`。通过 `ZipFile`，你可以高效且快速地操作 ZIP 文件。

`ZipFile` 的类构造函数接受一个名为 `compression` 的参数，该参数允许你在几种可用的数据压缩方法中进行选择。此参数是可选的，并以 `ZIP_STORED` 作为其默认值，这意味着 `ZipFile` 默认不会对输入数据进行压缩。

在这个例子中，`ZIP_STORED` 是 `zipfile` 中定义的常量。该常量为未压缩数据保存了一个数值。你还会发现由命名常量表示的其他压缩方法，例如用于 Deflate 压缩算法的 `ZIP_DEFLATED`。

当某个参数只能接受有限数量的有效值时，`ZipFile` 类构造函数中的 `compression` 参数就是使用常量来提供默认参数值的良好示例。

常量的另一个派上用场的场景是，当你拥有几个具有重复参数的函数时。假设你正在开发一个连接到本地 SQLite 数据库的应用程序。你的应用程序使用以下一组函数来管理数据库：

```python
import sqlite3
from sqlite3 import Error

def create_database(db_path):
    # 创建初始数据库的代码写在这里...
    pass

def create_connection(db_path):
    # 创建数据库连接的代码写在这里...
    pass

def backup_database(db_path):
    # 备份数据库的代码写在这里...
    pass

```

这些函数对你的 SQLite 数据库执行不同的操作。请注意，你所有的函数都共享 `db_path` 参数。

在开发应用程序时，你决定为你的函数提供一个默认的数据库路径，以便你可以快速测试它们。在这种情况下，你可以直接将该路径用作 `db_path` 参数的默认值。

然而，最好使用命名常量来提供默认数据库路径：

```python
import sqlite3
from sqlite3Error import Error

DEFAULT_DB_PATH = "/path/to/database.sqlite"

def create_database(db_path=DEFAULT_DB_PATH):
    # 创建初始数据库的代码写在这里...
    pass

def create_connection(db_path=DEFAULT_DB_PATH):
    # 创建数据库连接的代码写在这里...
    pass

def backup_database(db_path=DEFAULT_DB_PATH):
    # 备份数据库的代码写在这里...
    pass

```

这一小小的更新使你能够在开发过程中通过指向示例数据库来快速测试你的应用程序。它还提高了代码的可维护性，因为你可以在应用程序未来版本中出现的其他数据库相关函数中重复使用该常量。

最后，你会遇到这样的情况：你希望将具有某种行为的对象传递给类、方法或函数。这种做法通常被称为鸭子类型（duck typing），是 Python 中的一个基本原则。现在假设你的代码将负责提供所需对象的标准实现。如果你的用户想要一个自定义对象，那么他们应该自己提供。

在这种情况下，你可以使用常量来定义默认对象，然后将此常量作为默认参数值传递给目标类、方法或函数。查看以下假设的 `FileReader` 类的示例：

文件名：`file_handler.py`

```python
from readers import DEFAULT_READER

class FileHandler:
    def __init__(self, file, reader=DEFAULT_READER):
        self._file = file
        self._reader = reader

    def read(self):
        self._reader.read(self._file)

    # FileHandler 的实现写在这里...

```

该类提供了一种操作不同类型文件的方法。`.read()` 方法根据输入文件的特定格式，使用注入的 reader 对象来读取输入文件。

这是一个 reader 类的简单实现：

文件名：`readers.py`

```python
class _DefaultReader:
    def read(self, file):
        with open(file, mode="r", encoding="utf-8") as file_obj:
            for line in file_obj:
                print(line)

DEFAULT_READER = _DefaultReader()

```

此示例中的 `.read()` 方法接受文件的路径，将其打开，并将其内容逐行打印到屏幕上。这个类将扮演你的默认 reader 的角色。最后一步是创建一个常量 `DEFAULT_READER`，用来存储你的默认 reader 的实例。就是这样！你既拥有一个处理输入文件的类，又拥有一个提供默认 reader 的辅助类。

你的用户也可以编写自定义的 reader。例如，他们可以为 CSV 和 JSON 文件编写 reader。一旦他们编写好了给定的 reader，就可以将其传入 `FileHandler` 类构造函数中，并使用生成的实例来处理使用该 reader 目标文件格式的文件。


### 在真实的项目中处理常量

现在你已经知道了如何在 Python 中创建常量，接下来是时候学习如何在真实的项目中处理和组织它们了为此，你可以使用几种方法或策略。例如，你可以将常量放在：

* 与使用它们的代码相同的文件中
* 用于全项目常量的专用模块中
* 配置文件中
* 某些环境变量中

在下面的部分中，你将编写一些实际的示例，展示上述适当地管理常量的策略。

#### 将常量与相关代码放在一起

组织和管理常量第一种也是最自然的方法，是将它们与使用它们的代码定义在一起。使用这种方法时，你将在包含相关代码的模块顶部定义常量。

例如，假设你正在创建一个自定义模块来执行计算，并且你需要使用诸如圆周率、自然常数（欧拉数）等数学常量。在这种情况下，你可以这样做：

文件名：`calculations.py`

```python
"""This module implements custom calculations."""

# Imports go here...
import numpy as np

# Constants go here...
PI = 3.141592653589793
EULER_NUMBER = 2.718281828459045
TAU = 6.283185307179586

# Your custom calculations start here...
def circular_land_area(radius):
    return PI * radius**2

def future_value(present_value, interest_rate, years):
    return present_value * EULER_NUMBER ** (interest_rate * years)

# ...

```

在这个例子中，你在使用常量的同一个模块中定义了它们。

> **注意**：如果你想明确传达某个常量只能在其所在的模块中使用的意图，可以在其名称前面加上一个下划线（`_`）。例如，你可以写成 `_PI = 3.141592653589793`。这个前导下划线将该名称标记为非公共的，这意味着用户的代码不应直接使用该名称。

对于仅与给定项目中的单个模块相关的狭窄范围常量来说，将常量与使用它们的代码放在一起是一种快捷且合适的策略。在这种情况下，你可能不会在包含该模块本身的外部使用这些常量。

#### 为常量创建一个专用模块

组织和管理常量的另一种常见策略是创建一个专门的模块，将它们全部放入其中。此策略适用于在给定项目的许多模块甚至包中使用的常量。

此策略的核心思想是为常量创建一个直观且唯一的命名空间。要将此策略应用于你的计算示例，你可以创建一个包含以下文件的 Python 包：

```text
calc/
├── __init__.py
├── calculations.py
└── constants.py

```

`__init__.py` 文件会将 `calc/` 目录变成一个 Python 包。然后，你可以将以下内容添加到你的 `constants.py` 文件中：

文件名：`constants.py`

```python
"""This module defines project-level constants."""

PI = 3.141592653589793
EULER_NUMBER = 2.718281828459045
TAU = 6.283185307179586

```

一旦你将此代码添加到 `constants.py` 中，每当需要使用任何常量时，就可以导入该模块：

文件名：`calculations.py`

```python
"""This module implements custom calculations."""

# Imports go here...
import numpy as np
from . import constants

# Your custom calculations start here...
def circular_land_area(radius):
    return constants.PI * radius**2

def future_value(present_value, interest_rate, years):
    return present_value * constants.EULER_NUMBER ** (interest_rate * years)

# ...

```

请注意，你是使用相对导入直接从 `calc` 包导入 `constants` 模块的。然后，你使用完全限定名来访问计算所需的任何常量。这种做法改善了你对意图的传达。现在，由于有了 `constants` 前缀，`PI` 和 `EULER_NUMBER` 在你的项目中是常量这一事实变得完全清晰。

要使用你的 calculations 模块，你可以这样做：

```pycon
>>> from calc import calculations
>>> calculations.circular_land_area(100)
31415.926535897932
>>> from calc.calculations import circular_land_area
>>> circular_land_area(100)
31415.926535897932

```

现在，你的 `calculations` 模块驻留在 `calc` 包内部。这意味着如果你想使用 `calculations` 中的函数，你需要从 `calc` 导入 `calculations`。你也可以通过引用包和模块来直接导入函数，就像你在上面第二个示例中所做的那样。


#### 将常量存储在配置文件中

现在，假设你想在将给定项目的常量外部化方面更进一步。你可能需要将所有的常量保存在项目的源代码之外。为此，你可以使用外部配置文件。

以下是如何将常量移动到配置文件的示例：

文件名：`constants.ini`

```ini
[CONSTANTS]
PI=3.141592653589793
EULER_NUMBER=2.718281828459045
TAU=6.283185307179586

```

该文件使用 INI 文件格式。你可以使用标准库中的 `configparser` 模块来读取此类文件。

现在回到 `calculations.py` 并将其更新为类似以下内容：

文件名：`calculations.py`

```python
"""This module implements custom calculations."""

# Imports go here...
from configparser import ConfigParser
import numpy as np

constants = ConfigParser()
constants.read("path/to/constants.ini")

# Your custom calculations start here...
def circular_land_area(radius):
    return float(constants.get("CONSTANTS", "PI")) * radius**2

def future_value(present_value, interest_rate, years):
    return (
        present_value * float(constants.get(
            "CONSTANTS",
            "EULER_NUMBER"
        ))
    ) ** (interest_rate * years)

# ...

```

在这个例子中，你的代码首先读取配置文件，并将生成的 `ConfigParser` 对象存储在全局变量 `constants` 中。你也可以将此变量命名为 `CONSTANTS` 并将其作为常量在全局范围内使用。然后，你更新计算逻辑，从配置对象本身读取常量。

请注意，`ConfigParser` 对象将配置参数存储为字符串，因此你需要使用内置的 `float()` 函数将这些值转换为数字。

当你创建一个图形用户界面（GUI）应用程序，并且需要设置一些参数来定义加载和显示 GUI 时应用窗口的形状和大小等场景时，这种策略可能会非常有利。

#### 将常量作为环境变量处理

处理常量的另一种有用策略是：如果你使用的是 Windows，则将它们定义为系统变量；如果你使用的是 macOS 或 Linux，则将它们定义为环境变量。

这种方法通常用于在不同环境中配置部署。你还可以将涉及安全风险且不应直接提交到源代码中的常量保存在环境变量中。这些类型的常量的示例包括身份验证凭据、API 访问令牌等。

> **注意**：在将环境变量用于敏感信息时应小心，因为它们可能会在日志中或向子进程意外泄露。所有云服务提供商都提供某种更安全的密钥管理方式。

要使用此策略，你首先必须在操作系统中将常量导出为环境变量或系统变量。至少有两种方法可以做到这一点：

1. 在当前的 shell 会话中手动导出常量
2. 将你的常量添加到 shell 的配置文件中

第一种技术非常快捷实用。你可以用它对代码进行一些快速测试。例如，假设你需要将 API 令牌导出为系统变量或环境变量。在这种情况下，你只需运行以下命令：

* **Windows**
```cmd
C:\> set API_TOKEN="593086396372"

```


* **Linux + macOS**

这种技术的主要缺点是，你的常量只能从定义它们的命令行会话中访问。一个好得多的方法是让你的操作系统在每次启动命令行窗口时自动加载常量。

如果你使用的是 Windows，请查阅 Windows 上的 Python 编码环境：安装指南（*Your Python Coding Environment on Windows: Setup Guide*）中的“配置环境变量”（Configuring Environment Variables）部分，了解如何创建系统变量。按照该指南中的说明操作，并添加一个值为 `593086396372` 的 `API_TOKEN` 系统变量。

如果你使用的是 Linux 或 macOS，则可以转到你的主文件夹并打开 shell 的配置文件。打开该文件后，在末尾添加以下行：

* **Linux / macOS** (`.bashrc`)
```bash
export API_TOKEN="593086396372"

```



每当你启动终端或命令行窗口时，Linux 和 macOS 都会自动加载相应的 shell 配置文件。通过这种方式，你可以确保 `API_TOKEN` 变量在你的系统上始终可用。

一旦你为 Python 常量定义了所需的环境变量，就需要将它们加载到你的代码中。为此，你可以使用 Python `os` 模块中的 `environ` 字典。`environ` 的键和值分别代表环境变量及其值的字符串。

你的 `API_TOKEN` 常量现在已经存在于 `environ` 字典中。因此，你只需两行代码即可从其中读取它：

```pycon
>>> import os
>>> os.environ["API_TOKEN"]
'593086396372'

```

使用环境变量存储常量，并使用 `os.environ` 字典将它们读取到代码中，是配置依赖于应用程序部署环境的常量的一种有效方法。在处理云端服务时它特别有用，因此请将这项技术保留在你的 Python 工具包中。

### 探索 Python 中的其他常量

除了用户定义的常量之外，Python 还定义了几种可以被视为常量的内部名称。其中某些名称是严格的常量，这意味着一旦解释器运行，你就无法更改它们。例如，`__debug__` 常量就是这种情况。

在以下部分中，你将了解一些内部的 Python 名称，它们可以而且应该在你的代码中被视为常量。首先，你将回顾一些内置常量和常量值。

#### 内置常量

根据 Python 文档，“少量的常量存在于内置命名空间中”（来源）。文档中列出的前两个常量是 `True` 和 `False`，它们是 Python 的布尔值。这两个值也是 `int` 的实例。`True` 的值为 1，而 `False` 的值为 0：

```pycon
>>> True
True
>>> False
False
>>> isinstance(True, int)
True
>>> isinstance(False, int)
True
>>> int(True)
1
>>> int(False)
0
>>> True = 42
    ...
SyntaxError: cannot assign to True
>>> True is True
True
>>> False is False
True

```

请注意，`True` 和 `False` 名称是严格的常量。换句话说，它们不能被重新赋值。如果你尝试对它们重新赋值，就会得到一个 `SyntaxError`。这两个值在 Python 中也是单例对象（singleton objects），这意味着每个值都只有一个实例。这就是为什么恒等运算符 (`is`) 在上述最后的例子中返回 `True` 的原因。

另一个重要且常见的常量值是 `None`，它是 Python 中的空值。当你想要表达可空性（nullability）的概念时，这个常量值就会派上用场。就像 `True` 和 `False` 一样，`None` 也是一个单例且严格的常量对象，不能被重新赋值：

```pycon
>>> None is None
True
>>> None = 42
    ...
SyntaxError: cannot assign to None

```

`None` 作为函数、方法和类构造函数中的默认参数值非常有用。它通常用于传达变量为空的概念。在内部，Python 使用 `None` 作为没有显式 `return` 语句的函数的隐式返回值。

省略号字面量 (`...`) 是 Python 中的另一个常量值。这个特殊值与 `Ellipsis` 相同，并且是 `types.EllipsisType` 类型的唯一实例：

```pycon
>>> Ellipsis
Ellipsis
>>> ...
Ellipsis
>>> ... is Ellipsis
True

```

你可以将 `Ellipsis` 用作未编写代码的占位符。你还可以用它来替代 `pass` 语句。在类型提示（type hints）中，`...` 字面量传达了具有统一类型的未知长度集合的概念：

```pycon
>>> def do_something():
...     ...  # TODO: Implement this function later...
>>> class CustomException(Exception):
...     ...
>>> raise CustomException("some error message")
Traceback (most recent call last):
    ...
CustomException: some error message
>>> # A tuple of integer values
>>> numbers: tuple[int, ...]

```

由于 `Ellipsis` 常量值在语义上等同于英文省略号标点符号（…），因此它在许多情况下都能派上用场，并有助于提高代码的可读性。

另一个有趣且潜在有用的内置常量是 `__debug__`，正如你在本节开头所了解的那样。Python 的 `__debug__` 是一个布尔常量，默认值为 `True`。它是一个严格的常量，因为一旦解释器运行，你就无法更改它的值：

```pycon
>>> __debug__
True
>>> __debug__ = False
    ...
SyntaxError: cannot assign to __debug__

```

`__debug__` 常量与 `assert` 语句密切相关。简而言之，如果 `__debug__` 为 `True`，则你的所有 `assert` 语句都将运行。如果 `__debug__` 为 `False`，则你的 `assert` 语句将被禁用并且根本不会运行。此功能可以稍微提高生产代码的性能。

> **注意**：尽管 `__debug__` 也有一个双下划线名称，但它是一个严格的常量，因为一旦解释器运行，你就无法更改它的值。相比之下，下面一节中的内部双下划线名称应该被视为常量，但它们不是严格的常量。你可以在代码执行期间更改它们的值。然而，这种做法可能很棘手，需要高级知识。

要将 `__debug__` 的值更改为 `False`，你必须使用 `-O` 或 `-OO` 命令行选项在优化模式下运行 Python，这两个选项提供了两个级别的字节码优化。这两个级别都会生成不包含断言的优化版 Python 字节码。

### 有用的字符串和数学常量

你会在标准库中发现许多有用的常量。其中一些与某些特定的模块、函数和类紧密相连。其他的则更通性化，你可以在各种场景下使用它们。数学和字符串相关的常量就是这种情况，分别可以在 `math` 和 `string` 模块中找到。

`math` 模块提供以下常量：

```pycon

2.718281828459045
>>> # Pi (π)
>>> math.pi

>>> # Infinite (∞)
>>> math.inf
inf
>>> # Not a number (NaN)
>>> math.nan
nan
>>> # Tau (τ)
>>> math.tau
```

每当你编写与数学相关的代码，甚至是仅使用它们来执行特定计算的代码（例如“为可维护性重用对象”一节中的 `Circle` 类）时，这些常量都会派上用场。

以下是使用 `math.pi` 代替自定义 `PI` 常量的 `Circle` 的更新实现：

文件名：`circle.py`

```python
import math

class Circle:
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return math.pi * self.radius**2

    def perimeter(self):
        return 2 * math.pi * self.radius

    def projected_volume(self):
        return 4/3 * math.pi * self.radius**3

    def __repr__(self):
        return f"{self.__class__.__name__}(radius={self.radius})"

```

这个更新版本的 `Circle` 比原始版本更具可读性，因为它提供了关于圆周率常量来源的更多上下文，使其清楚地表明这是一个与数学相关的常量。

`math.pi` 常量还有一个优点，即如果你使用的是旧版本的 Python，你将获得 32 位版本的圆周率。相比之下，如果你在现代版本的 Python 中使用 `Circle`，你将获得 64 位版本的圆周率。因此，你的程序将自适应其具体的执行环境。

### 为常量添加类型注解

自 Python 3.8 起，`typing` 模块包含了一个 `Final` 类，允许你为常量添加类型注解。如果在定义常量时使用此类，就会告诉像 mypy 这样的静态类型检查器，你的常量不应该被重新赋值。通过这种方式，类型检查器可以帮你检测对常量的未授权赋值。

以下是使用 `Final` 定义常量的的一些示例：

```python
from typing import Final

MAX_SPEED: Final[int] = 300
DEFAULT_COLOR: Final[str] = "\033[1;34m"
ALLOWED_BUILTINS: Final[tuple[str, ...]] = ("sum", "max", "min", "abs")

# Later in your code...
MAX_SPEED = 450  # Cannot assign to final name "MAX_SPEED" mypy(error)

```

`Final` 类表示一种特殊的类型构造，它指示类型检查器：如果代码中的某个地方对该名称进行了重新赋值，则报告错误。请注意，尽管你会收到类型检查器的错误报告，但 Python 确实会改变 `MAX_SPEED` 的值。因此，`Final` 无法在运行时防止对常量的意外重新赋值。

### 在 Python 中定义严格常量

到目前为止，你已经了解了很多关于编程和 Python 常量的知识。你现在知道 Python 不支持严格的常量。它只有变量。因此，Python 社区采纳了使用大写字母的命名规范，以此传达某个特定变量实际上是一个常量的意图。

所以，在 Python 中，你没有常量。相反，你拥有的是永不改变的变量。如果你正在参与一个有许多不同水平程序员参与的大型 Python 项目，这可能会成为一个问题。在这种情况下，最好有一种机制来保证严格的常量——即程序启动后任何人也无法更改的常量。

因为 Python 是一种相当灵活的编程语言，你会发现有几种方法可以实现使常量不可更改的目标。在接下来的几个小节中，你将学习其中的一些方法。它们都涉及到创建一个自定义类并将其用作常量的命名空间。

为什么要使用类作为常量的命名空间？在 Python 中，任何名称都可以随心所欲地重新绑定。在模块级别，你没有合适的工具来防止这种情况发生。因此，你需要使用类，因为类比模块提供了更多的自定义工具。

在接下来的小节中，你将学习几种将类用作严格常量命名空间的不同方法。

### .**slots** 属性

Python 类允许你定义一个名为 `.__slots__` 的特殊类属性。该属性将包含一系列用作实例属性的名称。

你将无法向带有 `.__slots__` 属性的类中添加新的实例属性，因为 `.__slots__` 阻止了实例 `.__dict__` 属性的创建。此外，没有 `.__dict__` 属性意味着在内存消耗方面进行了优化。

通过使用 `.__slots__`，你可以创建一个用作只读常量命名空间的类：

```pycon
>>> class ConstantsNamespace:
...     __slots__ = ()
...     PI = 3.141592653589793
...     EULER_NUMBER = 2.718281828459045
...
>>> constants = ConstantsNamespace()
>>> constants.PI
3.141592653589793
>>> constants.EULER_NUMBER
2.718281828459045
>>> constants.PI = 3.14
Traceback (most recent call last):
    ...
AttributeError: 'ConstantsNamespace' object attribute 'PI' is read-only

```

在这个例子中，你定义了 `ConstantsNamespace`。该类的 `.__slots__` 属性包含一个空元组，这意味着此类的实例将没有属性。然后，你将常量定义为类属性。

下一步是实例化该类，以创建一个包含所有常量的命名空间变量。请注意，你可以快速访问特殊命名空间中的任何常量，但不能为其赋予新值。如果你尝试这样做，就会得到一个 `AttributeError`。

通过这项技术，你可以保证团队中的其他人无法更改常量的值。你已经实现了严格常量的预期行为。

### `@property` 装饰器

你还可以利用 `@property` 装饰器来创建一个用作常量命名空间的类。为此，你只需要将常量定义为属性，而不为它们提供 setter 方法：

```pycon
>>> class ConstantsNamespace:
...     @property
...     def PI(self):
...         return 3.141592653589793
...     @property
...     def EULER_NUMBER(self):
...         return 2.718281828459045
...
>>> constants = ConstantsNamespace()
>>> constants.PI
3.141592653589793
>>> constants.EULER_NUMBER
2.718281828459045
>>> constants.PI = 3.14
Traceback (most recent call last):
    ...
AttributeError: can't set attribute 'PI'

```

因为你没有为 `PI` 和 `EULER_NUMBER` 属性提供 setter 方法，所以它们是只读属性。这意味着你只能访问它们的值，而不可能为其中任何一个赋新值。如果你尝试这样做，就会得到一个 `AttributeError`。

### `namedtuple()` 工厂函数

Python 的 `collections` 模块提供了一个名为 `namedtuple()` 的工厂函数。该函数允许你创建支持命名字段的元组子代类，并使用点记法来访问其项，就像 `tuple_obj.attribute` 一样。

与常规元组一样，命名元组实例是不可变的，这意味着你不能就地修改现有的命名元组对象。不可变性听起来非常适合用来创建一个充当严格常量命名空间的类。

具体操作如下：

```pycon
>>> from collections import namedtuple
>>> ConstantsNamespace = namedtuple(
...     "ConstantsNamespace", ["PI", "EULER_NUMBER"]
... )
>>> constants = ConstantsNamespace(3.141592653589793, 2.718281828459045)
>>> constants.PI
3.141592653589793
>>> constants.EULER_NUMBER
2.718281828459045
>>> constants.PI = 3.14
Traceback (most recent call last):
    ...
AttributeError: can't set attribute

```

在这个例子中，你的常量扮演了底层命名元组 `ConstantsNamespace` 中字段的角色。一旦你创建了命名元组实例 `constants`，就可以通过使用点记法（如 `constants.PI`）来访问常量。

因为元组是不可变的，所以你无法修改任何字段的值。因此，你的常量命名元组对象是一个成熟的严格常量命名空间。

### `@dataclass` 装饰器

顾名思义，数据类（data classes）主要是包含数据的类。它们也可以有方法，但那不是它们的主要目标。要创建一个数据类，你需要使用来自 `dataclasses` 模块的 `@dataclass` 装饰器。

如何使用这种类型的类来创建严格常量命名空间？`@dataclass` 装饰器接受一个 `frozen` 参数，该参数允许你将数据类标记为不可变的。如果它是不可变的，那么一旦创建了给定数据类的实例，你就无法修改其实例属性。

你可以使用数据类来创建一个包含常量的命名空间，方法如下：

```pycon
>>> from dataclasses import dataclass
>>> @dataclass(frozen=True)
... class ConstantsNamespace:
...     PI = 3.141592653589793
...     EULER_NUMBER = 2.718281828459045
...
>>> constants = ConstantsNamespace()
>>> constants.PI
3.141592653589793
>>> constants.EULER_NUMBER
2.718281828459045
>>> constants.PI = 3.14
Traceback (most recent call last):
    ...
dataclasses.FrozenInstanceError: cannot assign to field 'PI'

```

在这个例子中，你首先导入了 `@dataclass` 装饰器。然后，你使用该装饰器将 `ConstantsNamespace` 转换为数据类。为了使数据类不可变，你将 `frozen` 参数设置为 `True`。最后，你将常量定义为类属性来定义 `ConstantsNamespace`。

你可以创建此类的一个实例并将其用作常量命名空间。同样，你可以访问所有常量，但不能修改它们的值，因为该数据类是冻结的。

### `.__setattr__()` 特殊方法

Python 类允许你定义一个名为 `.__setattr__()` 的特殊方法。该方法允许你自定义属性赋值过程，因为 Python 会在每次属性赋值时自动调用该方法。

在实践中，你可以重写 `.__setattr__()` 来防止所有属性重新赋值，从而使你的属性不可变。你可以通过重写此方法来创建一个用作常量命名空间的类：

```pycon
>>> class ConstantsNamespace:
...     PI = 3.141592653589793
...     EULER_NUMBER = 2.718281828459045
...     def __setattr__(self, name, value):
...         raise AttributeError(f"can't reassign constant '{name}'")
...
>>> constants = ConstantsNamespace()
>>> constants.PI
3.141592653589793
>>> constants.EULER_NUMBER
2.718281828459045
>>> constants.PI = 3.14
Traceback (most recent call last):
    ...
AttributeError: can't reassign constant 'PI'

```

你对 `.__setattr__()` 的自定义实现不会对类的属性执行任何赋值操作。当你尝试设置任何属性时，它只会引发一个 `AttributeError`。此实现使属性不可变。同样，你的 `ConstantsNamespace` 表现得就像一个常量命名空间。
